# Roadmap MeteoCare

В этом документе собраны планы дальнейшего развития MeteoCare. Основной акцент — переход к использованию локальной языковой модели, улучшение качества AI-рекомендаций и расширение возможностей персональной аналитики.

Сейчас анализ погодных условий и формирование рекомендаций выполняются через облачный **Gemini API**. **Основное направление дальнейшего развития** — интегрировать локальную модель, которую можно будет отдельно дообучать на подготовленных данных и использовать непосредственно на Android-устройстве. Параллельно планируется улучшить персонализацию рекомендаций, хранение истории и надёжность приложения.

## 1. Локальная языковая модель

- Подобрать компактную языковую модель с поддержкой русского языка и возможностью запуска на мобильных устройствах.
- Подготовить набор данных на основе погодных показателей, пользовательских характеристик и примеров рекомендаций.
- Организовать отдельную среду для обучения и дообучения модели с использованием LoRA/QLoRA.
- Провести оценку качества ответов, оптимизировать и квантовать модель для мобильного использования.
- Интегрировать локальный запуск модели в Android-приложение.

*Примечание: обучение модели планируется выполнять отдельно от Android-приложения. На устройстве будет происходить непосредственно запуск модели и генерация рекомендаций.*

## 2. Развитие AI-рекомендаций

- Улучшить персонализацию рекомендаций с учётом профиля пользователя и погодных условий.
- Расширить анализ взаимосвязи метеорологических показателей и самочувствия.
- Добавить оценку качества и достоверности генерируемых рекомендаций.
- Предусмотреть переключение между локальной моделью и Gemini API.

## 3. Персональная аналитика

- Реализовать хранение истории погодных показателей и полученных рекомендаций.
- Добавить графики изменения погодных условий и пользовательских статусов.
- Предусмотреть просмотр статистики за выбранный период.
- Использовать накопленные данные для улучшения персонализации рекомендаций.

## 4. Улучшение работы с погодными данными

- Добавить возможность вручную выбирать местоположение.
- Реализовать сохранение нескольких городов для отслеживания погоды.
- Улучшить обработку ошибок сети и недоступности погодного сервиса.
- Предусмотреть кэширование последних полученных погодных данных.

## 5. Тестирование и надёжность

- Добавить unit-тесты для бизнес-логики и обработки погодных данных.
- Покрыть тестами формирование запросов и обработку ответов AI.
- Проверить работу уведомлений и фоновых задач на разных версиях Android.
- Улучшить обработку ошибок и защиту пользовательских данных.

---

## 📌 Предполагаемый порядок реализации

1. Подбор локальной модели и подготовка среды для обучения.
2. Формирование обучающего набора данных и дообучение модели.
3. Оценка качества, оптимизация и квантование модели.
4. Интеграция локального запуска модели в Android-приложение.
5. Реализация переключения между локальным AI и Gemini API.
6. Развитие персональной аналитики и истории рекомендаций.
7. Расширение возможностей работы с погодными данными.
8. Тестирование новых функций и повышение надёжности приложения.
